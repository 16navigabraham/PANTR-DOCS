# Error Handling

## Trade Failures

Trade tools always return `{ status: "SUCCESS" | "FAILED", txHash, error }`.

On failure the result also includes:
```json
{ "is_error": true, "IMPORTANT": "DO NOT tell the user the trade succeeded. It failed." }
```

`is_error` signals to Claude the tool call failed. The `IMPORTANT` field is an explicit override so Claude doesn't hallucinate a success message from ambiguous output.

| Error | Cause |
|-------|-------|
| `INSUFFICIENT_BALANCE` | Not enough SOL/ETH for amount + gas |
| `SLIPPAGE_EXCEEDED` | Price moved past tolerance |
| `TOKEN_NOT_FOUND` | CA doesn't exist on-chain |
| `SAFETY_BLOCKED` | Token failed safety check |
| `DAILY_LIMIT_REACHED` | User hit daily spend cap |
| `TRADING_PAUSED` | User paused trading |

## External Services

**Jupiter** — 2 retries with backoff. Quote failure → `FAILED` "No route found". TX failure → parse Solana error code.

**Base swaps** — 2 retries. Gas estimation failure → fallback gas limit. Reverted TX → return revert reason.

**Privy** — wallet creation failure logged, user told to retry. Signing failure aborts trade.

**RugCheck / GoPlus** — timeout or 5xx → return risk score 50 (neutral), log warning. Never blocks a trade on API failure.

**DEXScreener** — timeout → return cached result if available, otherwise empty. Claude tells user data is unavailable.

**SendGrid** — failed send logged, user told to check email or retry. Code stays valid 10 min so they can retry without requesting a new one.

---

## Redis Down

- Conversation starts fresh (no history), rate limit skipped, bot still responds.
- All Redis calls are wrapped in try/catch — no crash.

---

## Claude API Failures

2 retries with backoff. `overloaded_error` (529) → retry once after 2s. After retries exhausted → "I'm having trouble thinking right now, try again in a moment."

Tool loop capped at 5 rounds. If Claude keeps calling tools without settling, loop breaks and returns the last partial response.

---

## Bot-Level

All message handlers are wrapped in try/catch. Any unhandled throw → log with userId + chatId → user gets "Something went wrong. Try again." Bot stays alive.

---

## Auto-Sell Failures

Sell fails (slippage, RPC error) → logged as `FAILED` trade → user notified via Telegram. Position stays open, next price check retries if conditions still met.

---

## Scheduled Actions

Tool fails at execution time → `ScheduledActionStatus` → `FAILED` → user notified. Not retried automatically.

---

## Monitor Poller

Per-monitor errors caught individually. Bad config → monitor `CANCELLED` + user notified. RPC/API timeout → skip this tick, retry next (60s).
