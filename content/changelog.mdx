## v1.0.1 — Robinhood Chain + Uniswap Trading API + ERC-8004 Live Metadata
*2026-07-09 → 07-10*

### Added
- **Robinhood Chain** (chain ID 4663, Arbitrum L2) — full trading support: WETH
  (`0x0Bd7D308...`), USDG (`0x5fc5360D...`, USD-pegged, 6 decimals), RPC + WebSocket

  3-step flow: check approval → quote → swap. Covers V2/V3/V4/UniswapX automatically from
  one API surface. Active on BASE, ETHEREUM, and ROBINHOOD as the *first* path tried in
  `executeSwap` (buy) and `executeSell`; existing aggregators remain as fallback. Key
  details: native ETH passed as zero address, 500 bps default slippage, 20% gas buffer on
  quoted limit.
- **`/api/agent-metadata` endpoint** — serves ERC-8004 JSON live from the Express server;
  no IPFS or Pinata required. On-chain URI (`setAgentURI`) now points at
  `https://api.pantr.xyz/api/agent-metadata`, so metadata updates automatically with every
  deploy. Service types use the registry-recognized names (`"web"`, `"A2A"`) and include
  full x402 payment details and OKX marketplace link.
- **`/.well-known/agent-registration.json`** in pantr-client (Vercel) — satisfies 8004scan
  domain-verification for `pantr.xyz`; declares both agentId 50984 (Base) and 93 (Mantle).

### Changed
- **`UNISWAP_API_KEY`** and **`ROBINHOOD_WS_URL`** added to env schema (both optional;
  Uniswap Trading API silently skipped if key is absent; Robinhood monitoring skipped if WS
  URL is absent).
- `scripts/update-agent-uri.js` rewritten — drops all Pinata/IPFS code; calls `setAgentURI`
  with `${API_URL}/api/agent-metadata`. Only needs `MANTLE_AGENT_KEY` + `API_URL`.

*2026-06-26 → 07-02*

### Added
- **LLM FOMO nudge** (`c3831d1`) — when an un-funded user's tracked alpha caller fires and
  they miss the trade, Claude generates a personalised "here's what you missed" DM with
  the token, caller name, and how much a $100 buy would be worth now. Drives funded
  conversion.
- **Full alpha detection→execution trace** (`ebf0651`) — `detectedAt` timestamp captured
  the moment a caller message is received; paired with `executedAt` on the trade record.
  Enables latency analytics: time from alpha signal to on-chain buy.
- **Admin trade-trace endpoint** (`44961fc`) — `GET /admin/trade-trace/:tradeId` returns
  anonymised latency breakdown (detection → quote → send → confirm) for stat drill-down
  without exposing user PII.
- **Native price warm-keeper** (`ce25ebe`) — a background task polls native token prices
  (SOL/ETH/BNB/MNT/TON) every 30s and writes to Redis so the 429-lifeboat always has a
  fresh value. Lifeboat TTL dropped from 6h → 1h so stale prices never survive overnight.
- **Personalised activation nudges** (`560b60b`) — users who deposited but haven't made a
  first trade receive a tailored DM (wallet balance shown, one-tap "buy" suggestion for a
  trending token). Sent once; logged to prevent repeat.
- **Low-balance DM on missed alpha** (`697e83a`) — if a user's funded wallet is below the
  $3 trade minimum when an alpha fires, they get a "top-up to catch the next one" prompt.
- **Daily limit on automated mirror + DCA buys** (`fdb5a17`) — prevents a single prolific
  caller from triggering unlimited auto-buys in one day; configurable per user.
- **Admin user search by ID** (`6008d4e`) — `GET /admin/user/:id` works with both numeric
  IDs and the masked log form (`123***789`) so support tickets can be triaged from logs.

### Fixed
- **Birdeye backoff extended** — Birdeye 429s previously triggered a 60s cooldown; raised
  to 15 min (matching GeckoTerminal). Prevents cascading 429 storms when Birdeye is busy.
- **Batch CoinGecko native price calls** (`697e83a`) — instead of one HTTP call per chain,
  all native tokens fetched in a single `?ids=solana,ethereum,...` request. Cuts boot
  CoinGecko calls 6→1.
- **Turso `tcp_refused` retry** (`f4ecdb5`) — transient Railway→Turso TCP errors in the
  auto-sell loop now retry up to 3× with 1s backoff instead of crashing the cycle.
- **Turso 502/503 retry on reads** (`5d384f3`) — gateway-level errors on DB reads retry
  similarly; prevents monitor data loss on Turso cold-starts.
- **TON deposit monitor balance polls** (`6f3c2ec`) — Toncenter API calls now include the
  `api_key` header; unauthenticated calls were being rate-limited and dropping deposits.
- **Wallet-tracker dedup crash** (`2105850`) — the dedup query used a Postgres JSON-path
  filter (`@>`) which doesn't exist in SQLite/libsql; switched to an application-level
  filter.
- **UNKNOWN token symbols in notifications and admin top-tokens** (`38ac4e3`,`a189ead`) —
  a background backfill now resolves and persists symbols for trades recorded with
  `UNKNOWN`; admin stats endpoint makes this non-blocking so it doesn't delay the response.
- **Auto-sell eligible-users lookup throttled** (`4125a9d`) — the 5s auto-sell loop was
  hitting the DB to fetch premium-eligible users every cycle; results now cached in Redis
  with a 60s TTL, reducing DB read load ~6×.

## v0.8.0 — Reliability, Jito & Referral Payouts
*2026-06-19 → 06-25*

### Added
- **Parallel-quote Solana routing** (`c337948`) — buy requests race Jupiter and
  PumpPortal quotes in parallel (`Promise.allSettled`); the first winning quote is sent.
  Graduated pump tokens remain Jupiter-first; bonding-curve tokens remain PumpDirect-first
  with the parallel quotes already warm when direct fails. Eliminates the triple-send bug
  on the bonding-curve fallback path.
- **Jito auto-enable** (`4384289`) — Jito MEV protection is now always attempted at
  startup via a reachability probe; `JITO_ENABLED` env flag removed (was error-prone).
  Gracefully falls back to standard RPC when Jito is unreachable.
- **Referral program** (`a383041`, `71569d3`, `78c047a`, `7b4daaf`) — `$2` payout on
  first subscription via referral link; automated SOL payout from fee wallet (phase 1);
  automated EVM payout across Base/BSC/Mantle (phase 2). Admin-gated, idempotent, capped.
  Payout tx hashes recorded as an audit trail. *Note: subsequently removed — payouts
  replaced by fee revenue model.*
- **`/bot self-diagnose` tool** (`410b441`) — Claude can call `self_diagnose()` to report
  which external services (Birdeye, Jupiter, DexScreener, Turso, etc.) are reachable. Used
  to explain failures to users in plain language rather than surfacing raw errors.
- **Native price Redis lifeboat** (`7b5a275`) — before every provider call, the last known
  price is written to Redis. On a 429 cascade, the lifeboat value is served so auto-sell
  keeps running on stale-but-present data instead of halting.

### Fixed
- **Jito block-engine host** (`30af01a`) — the hostname `jito.labs.io` has no DNS record;
  the actual endpoint is `jito.wtf`. The "Railway DNS block" was a dead hostname.
- **Graduated pump.fun token double-send** (`f210fe1`) — PumpPortal and Jupiter were
  launched in parallel for graduated tokens, each placing a real on-chain transaction.
  Now sequential with no fallback on timeout (double-buy guard). Regression test added.
- **Heap leak / OOM** (`d4e0ab8`) — `memCache` (in-process price cache) was never pruned;
  long-running containers accumulated stale entries until OOM. Now swept on every cache set
  (evict entries older than TTL).
- **`@solana/spl-token` upgrade** (`031396e`) — bumped from 0.1.8 → 0.4.14; fixes
  withdrawal failures on SPL token accounts created with the newer ATA program.
- **Stale signed tx on confirmation timeout** (`b53961f`) — when `confirmTransaction`
  timed out, the retry path was re-signing the *same* already-submitted transaction,
  risking a duplicate on-chain. Now: timeout → return the existing tx hash; only build a
  fresh tx on a fresh retry.
- **Withdrawal anomaly detection** (`99eba61`) — `redis.zRangeByScore` doesn't exist in
  the Upstash SDK (it's `zrangebyscore`, lowercase); anomaly alerts were silently failing.
  Also fixed BSC balance provider (wrong RPC was selected).
- **All-chain missing-wallet backfill restored** (`71d941d`) — dormant users who deposited
  on one chain before other chains were added had missing wallet rows; the backfill was
  accidentally removed in v0.6.5. Re-added as a boot-time pass (idempotent, non-blocking).
- **npm moderate vulnerability** (`4e6a4f1`) — `npm audit fix` applied for one resolvable
  moderate advisory without touching money-critical libs.

### Changed
- Admin `total charged per user` now sums pay-per-use alpha charges + premium price with
  individual breakdown fields, instead of showing one opaque total.

## v0.7.1 — Stability & Onboarding Bug-Bash
*2026-06-17 → 06-18*

A focused round of production fixes found during live testing — MTProto reliability,
channel/group resolution, demo mode, multi-chain wallets, settings, and dependency security.

### Fixed — MTProto (alpha tracking)
- **Sessions self-revoking (`AUTH_KEY_DUPLICATED`).** The reconnect guard spawned a
  *duplicate* client on every connection blip while gramjs was already auto-reconnecting
  the same session → Telegram saw two connections on one auth key and permanently
  revoked it. Layer-1 now observes only (lets gramjs self-heal); the heartbeat
  disconnects the old client before any rebuild.
- **Deploy-overlap revocation.** Graceful shutdown didn't disconnect MTProto, so a
  rolling Railway deploy briefly ran old + new containers on the same session → same
  revocation. Added `stopAll()` to release auth keys on `SIGTERM`.
- **Channel + group messages silently stopped after a reconnect.** Broadcast channels
  use a separate update stream that goes stale across a reconnect; the previous code
  re-primed it as a side effect of recreating the client, which the revocation fix
  removed. Now `getDialogs` re-primes channel+group updates on reconnect (and as a
  5-min heartbeat safety net) — *without* recreating the client.
- **Logging cleaned up** — per-chat resolution spam replaced with one grouped
  success-rate line per listener: `MTProto: chats 3/3 resolved (100%)`.
- **Channel vs group could not be distinguished (channel alpha silently dropped).** A
  group and a channel with the same name were indistinguishable, so adding "the channel"
  actually resolved to the group and the channel was never subscribed. Two root causes:
  (1) the name search matched when *search contained title*, so "AbrahamNAVIG channel"
  hijacked a group named "AbrahamNAVIG"; (2) classification used `className` only, but in
  MTProto a `Channel` is both broadcast channels *and* supergroups — the real
  distinguisher is the `broadcast`/`megagroup` flags
  ([core.telegram.org/constructor/channel](https://core.telegram.org/constructor/channel)).
  Now: proper `broadcast`/`megagroup` classification decides the match path, the buggy
  match half is removed, the `groupType` ("channel"/"group") param and a trailing type
  word in the name both act as disambiguation hints, and on a true name collision Pantr
  **asks** which one instead of silently guessing.
- **Channel alpha silently dropped even after it resolved correctly.** A broadcast channel
  posts *as the channel*, not as the caller — but the NewMessage handler matched by sender
  username, failed, and consumed the dedup slot, blocking the Raw handler that *would* have
  matched by entity ID. Now broadcast channels are matched by entity ID in both handlers
  (`_matchCallerByEntityId`), guarded by a regression test. Groups still match by sender.
- **`groupType` now disambiguates directly.** When a group and channel share a name,
  answering "channel"/"group" (or passing the `groupType` param) resolves the right entity
  immediately — no invite link or numeric ID required.

### Fixed — Demo mode
- **`reset_demo` did nothing.** There was no LLM tool for it, so "reset demo" mapped to
  `set_trading_mode` (a no-op). Added a real `reset_demo` tool that clears demo trade
  history and restores the balance.
- **Demo balances depleted instantly + missing chains.** Balances were native-unit with
  a broken `amountUsd/100` deduction (a $50 Base buy "spent" ~$1,250 of ETH), and BSC/TON
  had no pool — they silently drained the tiny shared ETH pool. Now **USD-notional pools
  per chain**, seeded **$10,000 each across all five chains** (Solana/Base/BSC/Mantle/TON),
  deducting the actual trade USD and returning sell proceeds.
- **Couldn't sell an open demo position.** `simulateSell` matched the token address
  exactly, but EVM addresses are case-insensitive (checksummed buy vs lowercased sell) →
  "no open position." Now matched case-insensitively (and the portfolio nets them as one).
- **Partial demo buys corrupted cost basis.** A buy deducted `min(amount, balance)`, so a
  $50 buy on a $2 balance "succeeded" — recording a $50 position funded by $2, and leaving
  a `$-0.00` balance. Demo buys now require the **full** balance and reject cleanly
  ("insufficient demo balance") otherwise.
- **`reset_demo` and balance display** finalized — clean per-chain USD pools, "reset demo"
  works via chat, balances render as plain USD (no misleading native-token labels).

### Fixed — Price data
- **Constant 429 storm from rate-limited providers.** Tokens that *no* provider could price
  (dead/illiquid/pre-index) re-ran the full Jupiter→DexScreener→Birdeye→GeckoTerminal
  cascade every cycle, keeping GeckoTerminal/Birdeye in perpetual backoff. Added a
  **negative cache**: a token no provider can price is marked "unpriceable" for 5 min and
  skipped, while any real price (REST or the WSS stream) clears the mark instantly. Tokens
  with even a stale price are always served — held positions are never starved.

### Fixed — Wallets
- **EVM wallets got a different address per chain.** Base/BSC/Mantle were created
  concurrently, each missing the not-yet-committed shared anchor → three separate Privy
  wallets. EVM creation is now serialized per user (first creates the anchor, rest reuse
  it). A backfill **consolidation pass** repairs already-split users by repointing the
  divergent rows to one canonical EVM address (idempotent; loud log if a divergent
  address ever held funds).
- **Removed the obsolete TON/missing-chain wallet backfill.** `ensureWallets()` creates any
  missing chain on demand (and signup creates all five), so the boot-time missing-chain
  backfill was dead weight. Boot now only runs the one-off EVM-address consolidation.

### Fixed — Settings & security
- **BSC/TON (and web Mantle) buy-amount updates silently dropped** — the fields were
  advertised to the LLM but missing from the `update_settings` allow-list and the
  settings API schema, so updates were filtered out. Added.
- **Dependency vulnerabilities: 6 high → 0.** Patched `ws`, `bn.js`, and `hono` via
  scoped npm `overrides` — without downgrading the money-critical libs (`ethers`,
  `@privy-io/*`, `tonweb`) that `npm audit fix --force` wanted to roll back.
- **CI lint fix** — the lint job had no dependency-install fallback, so a lockfile change
  made it fetch a wrong fresh ESLint; now installs on cache miss and pins the local one.

## v0.7.0 — Lightning Sell-Side: Rug Exit + Real-Time WSS + Buy Speed Tiers
*2026-06-17*

### Added
- **Rug Exit (always-on)** — `src/services/rug-detector.js`. A velocity-based detector
  that closes a position 100% the instant its price collapses ≥50% from a rolling peak
  within 180s — catching rugs/LP-pulls that stop-loss can't, including during the 5-min
  post-buy grace period where stop-loss is intentionally off. Core agent behaviour, no
  setup, single "🚨 Rug Exit" notification on trigger. Tunable via `RUG_DROP_PCT` /
  `RUG_WINDOW_SECS`.
- **Real-time WSS pricing (always-on)** — `src/services/price-stream-manager.js`
  subscribes to held pump.fun bonding-curve accounts over the RPC WebSocket and
  recomputes price the instant reserves change (same reserve decode `pumpswap-direct`
  uses for real swaps). Feeds both the auto-sell price cache and the rug detector's
  velocity window sub-second. Graceful REST fallback on any failure — can only make
  pricing fresher, never break it.
- **Buy speed tiers** — `priorityFeeTier` (auto/fast/turbo/custom) on `UserSettings`.
  Auto picks a congestion-aware dynamic priority fee; Fast/Turbo bid 1.6×/2.5× to land
  buys front-of-queue; Custom takes an exact µLam/CU. Set by chat ("set buy speed to
  turbo"). Resolution in `solana-swap.js` `getTieredPriorityFee`, threaded through the
  orchestrator into every Solana buy route.
- **Durable ticker resolution** — `resolveTokenMeta` now persists resolved symbols in
  the `TokenCache` table, so PnL cards/portfolio never fall back to "TOKEN"/raw address
  during provider 429 backoffs.

### Changed
- **Auto-sell refactored to a pure core** — `src/services/auto-sell-core.js` holds the
  decision logic (holdings netting, trigger evaluation) as pure, unit-tested functions;
  live and demo paths now share one source of truth instead of two diverging copies.
  Behaviour preserved (all existing auto-sell tests green) + new core/detector tests.
- **Removed feature gates** — `RUG_DETECT_MODE` and `PRICE_STREAM_MODE` env flags
  retired; both features are simply on with graceful fallbacks. Fewer knobs to manage.

## v0.6.5 — Infra Migration: Turso + Railway + Pay-Per-Use
*2026-06-08 → 06-09*

Platform consolidation — moved off a spread of services onto a leaner stack, and
simplified the revenue model.

### Changed
- **Database: Neon Postgres → Turso (libsql).** `DATABASE_URL` now points at Turso.
  Because the original tables were created with `prisma db push` and the legacy
  migrations are Postgres-syntax (which libsql can't parse), `prisma migrate deploy`
  was replaced with a **custom libsql migration runner** (`scripts/migrate.js`) that
  baselines legacy migrations and only executes an allowlist of SQLite-safe ones. A
  `PRAGMA`-based `ensureColumns` safety net adds any missing columns on every boot —
  this is how new settings columns land without a formal migration.
- **Hosting: Render → Railway.** Env vars injected at runtime by Railway; `/health`
  exempted from the HTTPS enforcer for Railway's health check. Fonts for PnL-card
  rendering installed via `railpack.json` `deploy.aptPackages` (Railway uses Railpack,
  not Nixpacks).
- **Revenue model: added usage-based charges alongside premium.** The legacy boolean
  fields (`isPremium`, `isOnTrial`, `autoRenew`) were dropped in favour of a date-based
  `premiumUntil` check; the `/month` premium subscription itself was briefly removed when
  pay-per-use was introduced, then **restored** (06-09, `checkPremiumExpiry` re-enabled).
  Current model, charged in native token:
  - **2% close fee** on every sell — all users (`PLATFORM_FEE_BPS=200`).
  - **$1 per alpha auto-buy** — non-premium only, post-paid on success (`ALPHA_CHARGE_USD`).
  - **$1 per auto-sell execution** — non-premium only, TP / SL / rug, on success (`AUTO_SELL_CHARGE_USD`).
  - **Premium ($20/mo, `PREMIUM_PRICE_USD`)** — exempt from the $1 charges (still pays the
    2% close fee); auto-renews in the chain the user last paid with.
  - **Demo users** are exempt from everything. Charge failures notify DEV, not the user.

### Added
- **BSC + TON support** — added together: real TON/BSC wallet creation, trading, and
  multi-chain alpha routing (`e71b830`, `507465c`, `3ab7c9f`). Pantr now spans
  Solana / Base / BSC / Mantle / TON.

## v0.6.0 — MTProto Regression Fix + Demo Sells + Rich Cards + Gas Fix
*2026-05-24*

### Fixed
- **MTProto listener regression** — `_logId()` (log masking helper, formerly `_shortId`) was accidentally used inside Prisma `WHERE` clauses in `startListening`, `_saveSession`, `refreshSubscriptions`, and `revokeSession`. Masked IDs never matched DB records, so all user listeners silently failed to start after deploy. Renamed helper to `_logId` throughout to make log-only intent obvious; all Prisma queries now use raw `userId`.
- **Double-buy on channel posts** — gramjs fires both `NewMessage` and `Raw(UpdateNewChannelMessage)` for the same broadcast channel message, causing two buys per CA. Fixed with `_dedupMsg(chatEntityId, msgId)` in `mtproto-manager.js` — an in-memory Set with 5s TTL that both handlers check before processing.
- **Demo sells blocked** — `sell_token` in `tool-executor.js` returned an error in demo mode instead of executing. Implemented `demoService.simulateSell()` which aggregates net token position from prior demo trades, fetches live price, creates a SELL `DemoTrade`, and increments the demo balance. Demo sells now work end-to-end.
- **ThreatMonitor Upstash API mismatch** — `redis.zAdd` / `redis.zRangeByScore` don't exist in the Upstash SDK. Fixed: `zadd` (lowercase), `member:` field instead of `value:`, `zrangebyscore` instead of `zRangeByScore`.
- **EVM withdrawal gas mismatch** — `_withdrawEvm` calculated `adjustedAmount = balance - gasCost` using one `maxFeePerGas` value, then called `signer.sendTransaction()` without passing it — ethers re-fetched fee data at submit time, getting a higher price, causing the node's balance check to fail. Fix: lock `maxFeePerGas` at estimate time and pass the same value to `sendTransaction`. Gas buffer also increased from 20% → 30%.

### Added
- **Demo sell simulation** (`src/services/demo-service.js`) — `simulateSell({ userId, tokenAddress, chain, percentage })` computes net tokens held from trade history, prices via `priceOracle.getTokenPrice`, records a SELL demo trade, returns tx hash + amounts for realistic DM formatting.
- **Rich position cards** (`/positions`) — both demo and live positions now show: token symbol/name, DEX · MC · Liq · Price line, tokens held, cost basis, current value, PnL with % and emoji, explorer links (DexScreener · Basescan/Solscan · BirdEye), CA. Data sourced from DexScreener via `fetchTokenPair`.
- **Rich trade notifications** (`notifications.js`) — `sendTelegramTradeConfirmed` now fetches live DexScreener pair data and shows DEX, MC, liquidity, and price for both BUY and SELL confirms. `sendTelegramPositionSummary` (auto-sell triggers) enriched with PnL, MC, liq, and token links.
- **Rich alpha buy DMs** (`alpha.js`) — demo buy DMs replaced bare text with full card: symbol/name, market summary, price, caller, spent→tokens, tx hash, explorer links.
- **`src/utils/market-format.js`** — shared formatting helpers: `fmtPrice` (subscript zero compression for micro-cap prices), `fmtNum`/`fmtTokenAmt` (K/M/B suffixes), `shortAddr`, `explorerLinks`, `pairSummary`.
- **`priceOracle.fetchTokenPair(address, chain)`** — DexScreener `/latest/dex/tokens/{address}` lookup filtered by chain slug, sorted by liquidity, with 60s mem-cache. Used by position cards and trade notifications.

### Changed
- **Demo UX language** — removed all "simulated trade" and "no real funds" phrasing from user-facing strings. Demo mode now reads: "live prices, no on-chain execution". The word "demo" is kept but the experience looks and feels like live trading.

## v0.5.0 — Trade Speed + Channel Alpha Fix + Stability
*2026-05-20*

### Fixed
- **Broadcast channel alpha tracking** — Raw handler was doing `callerEntityMap.has(channelId)` but `callerEntityMap` is keyed by caller username, not entity ID. Fix: reverse-iterate the map to find which caller owns the channel. Channel messages now correctly trigger alpha buys.
- **Jito enabled by default** — `JITO_ENABLED !== 'false'` defaulted ON when the env var was absent, adding ~2s DNS failure on every Solana buy. Changed to `=== 'true'` (opt-in).
- **Pump.fun token routing** — graduated tokens went to Jupiter first (fails with `Custom:6001` after graduation); now routes PumpPortal first and falls back to Jupiter. Cuts pump token buy latency significantly.
- **Sell using stale DB amount** — sell_token fell back to the DB buy record when the token wasn't in wallet, causing a Jupiter `Error 6024` swap attempt. Now returns an error immediately if on-chain balance is zero/missing.
- **Solana withdrawal rent reserve** — withdrawing full SOL balance left account below rent-exempt minimum (~890,880 lamports), failing simulation. Now reserves `rent_exempt + gas` before computing the withdrawal amount.
- **Double DM on failed alpha buy** — `notifications.js` sent both `⚠️ Alpha buy skipped` and `❌ Trade Failed` for the same event. Fixed: skip `sendTelegramTradeFailed` when `trade.alphaGroupId` is set.
- **Claude 529 model fallback** — on Anthropic overload, bot now switches to the configured fallback model (`CLAUDE_FALLBACK_MODEL`) instead of failing. Different models run on separate capacity pools so the fallback is effective.
- **Analytics volume counting** — analytics `/public` endpoint was counting BUY-only volume; corrected to count all confirmed trades (BUY + SELL) to match the admin dashboard definition.
- **Fee revenue query** — admin fee revenue was excluding old sell trades due to `AND action = 'BUY'` in the SQL fallback. Removed the filter so sell-side 2% fees are counted.
